# Plan — slice 1 "Calculator": REQ-DEMO-001@v1, REQ-DEMO-003@v1, REQ-DEMO-002@v1

Branch: `feat/calculator`. Build order follows `depends_on`: 001 → 003 → 002.

## What must be true

**REQ-DEMO-001@v1**
- When the Calculator page is opened, exactly two text boxes, one button and one
  answer label are visible, on a single page.

**REQ-DEMO-003@v1**
- Typing a minus sign into an empty text box leaves it empty.
- Typing a decimal point into a text box holding 12 leaves it holding 12.
- Typing a letter into an empty text box leaves it empty.
- Typing 25 into an empty text box leaves it holding 25.

**REQ-DEMO-002@v1**
- With 3 and 4 in the text boxes, pressing the button shows 7 in the answer label.
- With 0 and 5 in the text boxes, pressing the button shows 5 in the answer label.

## Approach

Plain JavaScript, no build step, no runtime dependencies. ES modules throughout
(`"type": "module"` in `package.json`).

Files:

| File | Purpose |
|---|---|
| `src/index.html` | The Calculator page: two `<input type="text" inputmode="numeric">` boxes, one `<button>`, one `<output>` answer label. Each has a visible `<label>`. CSP `default-src 'self'`. |
| `src/calculator.js` | Pure functions, no DOM. `toNumberText(text)` returns `text` with every character that is not a digit 0–9 removed. `addNumbers(first, second)` returns the Answer of two Number strings. |
| `src/app.js` | DOM wiring only. On each text box's `input` event, replaces its value with `toNumberText(value)` — this covers typing and pasting alike. On button `click`, writes `addNumbers(...)` into the answer label with `textContent`. |
| `src/server.js` | Tiny `node:http` static server for `npm start` and for Playwright. Serves only an allow-list of the three files above with explicit `Content-Type`; anything else is 404. No path joining from the URL, so no traversal surface. |
| `package.json` (root) | `start`, `test`, `coverage`, `lint` scripts; `@playwright/test` as the only dev dependency. |
| `playwright.config.js` (root) | `webServer` runs `node src/server.js`; Chromium only. |

`type="number"` is deliberately **not** used: browsers let it accept `-`, `.`,
and `e`, which is exactly what REQ-DEMO-003 forbids.

## Decisions this forces

- **ADR: add `@playwright/test` as a dev dependency.** Belt B is required on
  every requirement and `node:test` cannot drive a browser. Dev-only; nothing
  ships to the child's browser.
- **ADR (small): input filtering on the `input` event rather than `type="number"`.**
  Records why the obvious control was rejected.

## What I am unsure about

- **Pressing the button with a text box empty.** The brief does not say, and the
  client asked us not to raise it. Proposed: the answer label stays blank until
  both text boxes hold a Number. Correct this if you would rather an empty box
  count as 0.
- **Very long Numbers.** Nothing limits length. Above 9,007,199,254,740,991 a
  JavaScript `Number` loses precision. Proposed: no limit, ignore it — a child
  will not type sixteen digits. Say if you want a `maxlength`.
- **`npm run lint`.** Gate G1 calls it. Proposed: `node --check` over `src/`
  and `tests/`, to avoid adding ESLint. Say if you want ESLint instead.

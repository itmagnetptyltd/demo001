# Plan — REQ-DEMO-004@v1 (CHG-0002, Subtract)

Slice 2 "Subtraction". Slice 1 is Done: REQ-DEMO-001@v3 already puts the
Subtract button on the page, and REQ-DEMO-003@v1 keeps the text boxes to whole
Numbers. Both dependencies are verified.

## What must be true

1. **c1:** 7 and 3, then **Subtract** pressed: the answer label shows 4.
2. **c2:** 5 and 5, then **Subtract** pressed: the answer label shows 0.
3. **c3:** 3 and 5, then **Subtract** pressed: the answer label shows -2.

The Answer is the first Number minus the second, and may be negative.

## Approach

| File | Change |
|---|---|
| `src/calculator.js` | Add `subtractNumbers(first, second)`, alongside `addNumbers`: parses both digit strings with radix 10 and returns first minus second. JSDoc to match. |
| `src/app.js` | Look up `#subtract` and give it a click handler that mirrors Add: when both boxes hold a Number, the answer label shows `String(subtractNumbers(...))`; otherwise it is cleared. The shared "both boxes filled, then show" step becomes one small function used by both buttons, so the two handlers can't drift apart. |
| `src/index.html`, `src/styles.css`, `src/server.js` | No change. |

`String(-2)` is `"-2"`, with an ASCII hyphen-minus, which is exactly what c3 says.


All existing tests stay as they are and must stay green. The Add browser tests
guard against the shared function breaking Add.

## What I am unsure about

   empty. I'll do what Add already does (the answer label is cleared) so the
   two buttons behave alike. No test is written for it, because no requirement
   asks for it.
2. **The heading `<h1>Add two numbers</h1>`.** Once Subtract works it describes
   only half the Calculator. No requirement names the heading, so changing it
   (or deciding to leave it) is your call, not part of this plan. If you want
   it changed, tell me the wording and I'll treat it as a `/note`-level tweak
   or a requirement, whichever you prefer.

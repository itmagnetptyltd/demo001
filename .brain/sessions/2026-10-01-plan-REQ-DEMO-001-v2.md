# Plan — REQ-DEMO-001@v2 (CHG-0001, child-friendly design)

Slice 1 "Calculator", branch `feat/calculator`. REQ-DEMO-002@v1 and
REQ-DEMO-003@v1 are already verified and are not touched.

## What must be true

1. **c1 (unchanged from v1):** exactly two text boxes, one button and one answer
   label are visible on a single page.
2. **c2:** top to bottom, the order is first text box, second text box, button,
   answer label. The horizontal centre of each is the horizontal centre of the page.
3. **c3:** the page background is not plain white.
4. **c4:** the button, each text box and the answer label each have a background
   colour, a border and a font size that differ from the browser's default for
   that control.

## Approach

All styling goes in a new stylesheet. The page's CSP is `default-src 'self'`,
which blocks inline `<style>` and `style=""`, so an external same-origin file is
the only option that keeps the CSP.

| File | Change |
|---|---|
| `src/styles.css` | **New.** `body`: soft sky-blue to sunshine-yellow gradient, full height. `main`: a white rounded card, `display: flex; flex-direction: column; align-items: center`, so every control shares one centre line. Text boxes, the button and the answer label: same width, large rounded corners, thick coloured border, large friendly font (system rounded stack, no web fonts because the CSP forbids them), coloured backgrounds. The Add button is bright orange with a hover/press effect. |
| `src/index.html` | Link `styles.css`. Each `<label>` sits above its text box inside the column. The "Answer:" wrapper is removed so the answer label is itself a centred item. No new visible controls, so c1 still holds and the "nothing else to distract" rationale is kept. |
| `src/server.js` | Add `/styles.css` (`text/css; charset=utf-8`) to the allow-list. |

No JavaScript changes.

**Belt B, new in `e2e/calculator.spec.js`** (the real proof of c2–c4, measured in Chromium):
```js
// @covers REQ-DEMO-001@v2
test('the controls are stacked top to bottom in order')
  // boundingBox().y strictly increasing: first box < second box < button < answer label
// @covers REQ-DEMO-001@v2
test('every control is centred on the page')
  // |box.x + box.width/2 - viewportWidth/2| <= 1 for each of the four controls
// @covers REQ-DEMO-001@v2
test('the page background is not plain white')
  // computed body background-image !== 'none' OR background-color not white
// @covers REQ-DEMO-001@v2
test.each(['button', 'first text box', 'second text box', 'answer label'])
  ('the %s does not look like the browser default')
  // compare computed background-color, border, font-size against the same element
  // created on an unstyled blank page (page.setContent) in the same browser
```

Belt B is defined against the browser's real defaults, not values I wrote down,
so the test cannot pass just because it repeats the stylesheet.

## Decisions this forces

- **Styling in an external `styles.css` file, not inline.** This is forced by the
  CSP. It's small, but worth a line in the ADR on input handling or its own ADR.

## What I am unsure about

- **The colours and font are my choice.** "Beautiful" and "kids like this" were
  turned into testable criteria ("not white", "not browser default"). The actual
  palette (sky-blue to yellow gradient, orange button, white card) is taste, and
  any palette passes the tests. Correct it now if you have colours in mind.
- **Belt A for c2–c4 is weak.** A unit test can check element order and that the
  stylesheet is linked. It cannot check centring or computed colours. Belt B is
  where those criteria are actually proven.
- **Phone width.** Not in the criteria. Proposed: the card is
  `width: min(90vw, 360px)`, so it stays centred and fits a phone, with no extra
  test.

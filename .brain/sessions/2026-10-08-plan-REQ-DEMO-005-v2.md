# Plan — REQ-DEMO-005@v2 (CHG-0006: the close button closes the tab)

Slice 4 "Close", reopened. Slice 3 is Done. Dependency REQ-DEMO-001@v4 is
verified; the close button (×, accessible name "Close") is already on the page.

## What must be true

1. **c1:** in a tab the browser lets the page close, pressing the close button
   closes the tab.
2. **c2:** with 3 and 4 typed and Add pressed (label shows 7), pressing close in
   a tab the browser will **not** let the page close leaves the boxes holding 3
   and 4 and the label showing 7. Nothing is cleared.

Browsers let a page close its tab only when a script opened it, or when the tab
has a single entry in its history. Otherwise `window.close()` is ignored.

## Approach

| File | Change |
|---|---|
| `src/app.js` | The close handler stops clearing and calls `window.close()` instead. Nothing else happens on click, so when the browser refuses, the Calculator is left exactly as it was (c2). |
| `src/calculator.js`, `src/index.html`, `src/styles.css`, `src/server.js` | No change. |

## Test skeleton

The three v1 tests ("close empties both boxes and the label", in A and B, and
"after close every control is still visible", in B) are **replaced**: the client
reversed that behaviour.

```js
// Belt A — tests/calculator.spec.js (stand-in document, as before, plus a
// stand-in window whose close() records that it was asked and does nothing,
// like a browser that refuses)
// @covers REQ-DEMO-005@v2
test('pressing close asks the browser to close the tab')
  // stand-in window.close was asked once
// @covers REQ-DEMO-005@v2
test('pressing close when the browser refuses leaves 3, 4 and 7 as they were')
  // boxes '3', '4'; add -> '7'; close -> still '3', '4', '7'

// Belt B — e2e/calculator.spec.js
// @covers REQ-DEMO-005@v2
test('pressing close closes a tab the page is allowed to close')
  // fresh page at '/' (one history entry); click Close; the page emits 'close'
// @covers REQ-DEMO-005@v2

  // navigate twice so the tab has two history entries (browser refuses);
  // type 3, 4; Add -> 7; click Close; page still open, boxes 3 and 4, label 7
```

## Decisions this forces

None that need an ADR.

## What I am unsure about

1. **The browser tests depend on Chromium's rule** for when a page may close
   itself (one history entry, or opened by script). That's the documented
   behaviour, and Playwright opens each test page fresh, so the "allowed" case
   should close. I'll confirm both cases actually behave this way while the
   tests are red, before trusting them.
2. **Asserting a call in belt A.** The testing rules prefer outcomes over
   calls. Outside a browser, "the tab closed" can only be seen as "close was
   asked", so that's what the stand-in records. The real outcome is proven in
   belt B.
3. **A child in a normal tab will usually see nothing happen.** That's the
   accepted trade-off recorded in REQ-DEMO-005@v2's rationale, not a defect.

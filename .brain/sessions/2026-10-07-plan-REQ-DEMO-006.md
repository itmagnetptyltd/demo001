# Plan — REQ-DEMO-006@v1, REQ-DEMO-007@v1 (CHG-0004, CHG-0005: Multiply and Divide)

Slice 3 "Multiply and Divide". Slice 1 is Done: REQ-DEMO-001@v4 already puts the
Multiply and Divide buttons on the page. REQ-DEMO-003@v1 keeps the text boxes to
whole Numbers. Both dependencies are verified.

## What must be true

REQ-DEMO-006@v1 (Multiply)

1. **c1:** 3 and 4, then **Multiply** pressed: the answer label shows 12.
2. **c2:** 0 and 5, then **Multiply** pressed: the answer label shows 0.

REQ-DEMO-007@v1 (Divide)

1. **c1:** 6 and 2, then **Divide** pressed: the answer label shows 3.
2. **c2:** 7 and 2, then **Divide** pressed: the answer label shows 3 r 1.
3. **c3:** 5 and 0, then **Divide** pressed: the answer label is empty.

## Approach

| File | Change |
|---|---|
| `src/calculator.js` | Add `multiplyNumbers(first, second)` returning the product, beside `addNumbers` and `subtractNumbers`. Add `divideNumbers(first, second)` returning **the Answer as text**: `""` when the second Number is 0; otherwise the whole quotient (`Math.trunc`), followed by `" r "` and the remainder (`%`) only when the remainder is not 0. Text rather than a number, because "3 r 1" is not a number and an empty Answer is not 0. JSDoc on both. |
| `src/app.js` | Look up `#multiply` and `#divide` and wire them through the existing `showAnswer`, which already does `String(operation(...))`, so a text result passes through unchanged. Widen the `showAnswer` JSDoc to `=> number \| string`. |
| `src/index.html`, `src/styles.css`, `src/server.js` | No change. |

## Test skeleton

```js
// Belt A — tests/calculator.spec.js
// @covers REQ-DEMO-006@v1
test('3 times 4 gives the Answer 12')          // multiplyNumbers('3', '4') === 12
// @covers REQ-DEMO-006@v1
test('0 times 5 gives the Answer 0')           // multiplyNumbers('0', '5') === 0
// @covers REQ-DEMO-007@v1
test('6 divided by 2 gives the Answer 3')      // divideNumbers('6', '2') === '3'
// @covers REQ-DEMO-007@v1
test('7 divided by 2 gives the Answer 3 r 1')  // divideNumbers('7', '2') === '3 r 1'
// @covers REQ-DEMO-007@v1

// Belt B — e2e/calculator.spec.js
// @covers REQ-DEMO-006@v1
test('3 and 4 then Multiply shows 12')
// @covers REQ-DEMO-006@v1
test('0 and 5 then Multiply shows 0')
// @covers REQ-DEMO-007@v1
test('6 and 2 then Divide shows 3')
// @covers REQ-DEMO-007@v1
test('7 and 2 then Divide shows 3 r 1')
// @covers REQ-DEMO-007@v1
test('5 and 0 then Divide leaves the answer label empty')
  // type 5, 0; press Add first so the label holds 5, then Divide; label has text ''
```

The last browser test presses Add first. Without that, an empty label after
Divide can't be told apart from Divide doing nothing at all.

## Decisions this forces

None that need an ADR.

## What I am unsure about

1. **An empty text box.** As with Add and Subtract, the label is cleared. No
   criterion asks for this, and no test is written for it.
2. **Very large products.** Nothing caps the size of a Number, so a long enough
   product goes past what JavaScript counts exactly (above about 9 quadrillion)
   and shows in exponent form. No criterion covers it. I am not handling it; it's
   a change record if it matters.
3. **"r" spacing.** The criterion text is `3 r 1`, a single space either side.
   The test checks exactly that string.

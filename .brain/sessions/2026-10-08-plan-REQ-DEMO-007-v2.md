# Plan — REQ-DEMO-007@v2 (CHG-0007, CHG-0008: decimal Divide, divide-by-zero message)

Slice 3 "Multiply and Divide", reopened for REQ-DEMO-007 only. REQ-DEMO-006@v1
is verified and not touched. Dependencies REQ-DEMO-001 and REQ-DEMO-003 are
verified.

## What must be true

1. **c1:** 6 ÷ 2 → the answer label shows `3`.
2. **c2:** 7 ÷ 2 → `3.5`.
3. **c3:** 3434 ÷ 5000 → `0.69`.
4. **c4:** 1 ÷ 3 → `0.33`.
5. **c5:** 5 ÷ 0 → `Oops! You can't divide by zero`.
6. **c6:** 5 ÷ 0 → the text boxes still hold 5 and 0.

The Answer is the quotient rounded to 2 decimal places, shown without trailing
zeros (so `3.5`, not `3.50`; `3`, not `3.00`).

## Approach

| File | Change |
|---|---|
| `src/calculator.js` | Rewrite `divideNumbers(first, second)`. Divisor 0: return the message `"Oops! You can't divide by zero"` (a named constant). Otherwise round the quotient to 2 places and return it as text via `String(Number(...))`, which drops trailing zeros. Rounding uses the exponent form (`Math.round(Number(`${q}e2`))` then `e-2`), not `Math.round(q * 100) / 100`, so halves round up correctly (e.g. 1.005 → 1.01 rather than 1). JSDoc updated to the new rule. |
| `src/app.js` | No change. `showAnswer` already writes whatever `divideNumbers` returns, and never touches the text boxes, so c6 holds already. |
| `src/index.html`, `src/styles.css`, `src/server.js` | No change. |

## Decisions this forces

None that need an ADR.

## What I am unsure about

1. **Results that round to 0.** 1 ÷ 1000 = 0.001 rounds to `0`. That follows the
   agreed rule, but a child may find "0" surprising. No criterion covers it.
2. **The message and an empty text box.** With a box empty, `showAnswer` clears
   the label before Divide runs, so 5 ÷ (empty) shows nothing, not the message.
   Only 5 ÷ 0 shows it. No criterion covers the empty case.
3. **The apostrophe.** The message uses a straight apostrophe (`can't`), exactly
   as recorded in ANSWERS.md.

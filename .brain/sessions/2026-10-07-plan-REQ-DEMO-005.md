# Plan — REQ-DEMO-005@v1 (CHG-0003: the close button clears)

Slice 4 "Close". Slice 3 is Done. REQ-DEMO-001@v4 already puts the close button
(×, accessible name "Close") in the card's top right corner; this slice gives it
behaviour. Its dependency, REQ-DEMO-001, is verified.

## What must be true

1. **c1:** with 3 and 4 typed and Add pressed (the answer label shows 7),
   pressing the close button leaves both text boxes empty and the answer label
   empty.
2. **c2:** after the close button is pressed, the two text boxes, the four
   operation buttons, the close button and the answer label are all still
   visible. Close clears; it does not hide or close anything.

## Approach

| File | Change |
|---|---|
| `src/app.js` | Look up `#close` and give it a click handler that sets both text boxes' `value` to `""` and the answer label's `textContent` to `""`. Nothing is hidden or removed. |
| `src/calculator.js`, `src/index.html`, `src/styles.css`, `src/server.js` | No change. |

## Test skeleton

Clearing lives only in the page script, so belt A can't test it through
`calculator.js`. Instead, belt A imports `src/app.js` into a small stand-in
document: an object whose `getElementById` returns plain objects with `value`,
`textContent` and `addEventListener`. The test then fires the close button's
click handler and checks the values. Each test imports `app.js` with its own
query string so no state is shared between tests.

```js
// Belt A — tests/calculator.spec.js (the only file `npm test` runs)
// @covers REQ-DEMO-005@v1
test('pressing close after 3 + 4 = 7 empties both text boxes and the answer label')
  // stand-in boxes '3', '4'; fire add click -> answer '7'; fire close click
  // -> first.value '', second.value '', answer.textContent ''

// Belt B — e2e/calculator.spec.js
// @covers REQ-DEMO-005@v1
test('3 and 4, Add, then close empties both text boxes and the answer label')
  // type 3, 4; click Add; status '7'; click Close; both textboxes have value '', status ''
// @covers REQ-DEMO-005@v1
test('after close, every control is still visible')
  // click Close; 2 textboxes, Add/Subtract/Multiply/Divide, Close and status all toBeVisible
```

All existing tests stay as they are and must stay green.

## Decisions this forces

None that need an ADR.

## What I am unsure about

1. **The stand-in document in belt A.** It's the only way to give this
   requirement a unit test without adding a DOM library. It checks behaviour
   (values after a click), not how the code is written. If you'd rather avoid
   it, the alternative is a dependency such as jsdom. That needs an ADR, and
   the JavaScript rules discourage adding dependencies.
2. **Focus after close.** No criterion says where the keyboard focus goes after
   clearing (moving it to the first text box would help a child start again).
   I'm leaving focus alone. Tell me if you want it moved; that would be a new
   criterion.
